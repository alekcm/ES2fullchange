# Диагностика зависания главного меню (25.10.2026)

## Итог (причина найдена, фикс в Managed/Assembly-CSharp.dll)

`GuiBoundAttribute.BindAllProperties` (firstpass) ищет свойства окна через
`GetMember("*", Property, FlattenHierarchy|NonPublic|Instance|IgnoreCase)` —
только non-public. Клонер публицизировал геттеры
`GuiModalWindow.BackgroundGroup` / `MainContainer` (код Совета читал их
напрямую), свойства становились публичными, AGE-биндинг их пропускал, и у
всех модальных окон «хром» оставался null → NullReferenceException в
корутине загрузки окон и вечный экран загрузки.

Фикс: чтение хрома перенесено внутрь класса окна
(`CouncilModalWindow.ChromeBound`), а клонеру запрещено публицизировать
аксессоры `[GuiBound]`-свойств (лог сборки: `kept non-public (GuiBound)`).

## Раунд 2 (по результатам первого: висят все, включая CloneOnly)

Первый раунд показал, что висит даже вариант без единого хука. Проверяем
саму «дельту» сборки по частям:

1. **DiagG_RoundTripRepair.dll** — baseline, просто переписанный нашим
   Cecil (+ починка единственного сломанного перехода в hacking-методе,
   который во фронтенде не вызывается). Ни клонированных типов, ни
   публицизации, ни хуков.
   - Если висит G — дальше не тестируйте: дело в самой Cecil-перезаписи.
2. **DiagE_TypesOnlyNoPublicize.dll** — G + все клонированные типы мода,
   но без публицизации и без хуков.

Интерпретация вместе с результатом D (= G + типы + публицизация, висит):

- G висит → виновата Cecil-перезапись сборки как таковая.
- G ок, E висит → фронтенду мешают сами клонированные типы.
- G ок, E ок, D висит → виновата публицизация членов игровых типов.

Остальное (как подставлять, «меню появилось / висит», без сейвов) — как
в описании первого раунда ниже.

## Раунд 1

Четыре тестовые сборки `Assembly-CSharp.dll` для поиска хука, из-за которого
игра висит на экране загрузки главного экрана (GUI NullReferenceException
при загрузке окон). Ванилла и baseline (0e0f215) запускаются — виноват наш
патч, теперь сужаем круг.

## Как тестировать

**Только проверка «главное меню появилось или висит». Не начинайте игру и не
загружайте сейвы с этими DLL** (в вариантах отключены куски геймплея).

Для каждого варианта: скопируйте файл в `EndlessSpace2_Data/Managed/`,
переименовав в `Assembly-CSharp.dll`, запустите игру, подождите ~30 секунд:
появилось главное меню = «запускается», вечный экран загрузки = «висит».
Затем выйдите из игры (Alt-F4, если висит) и ставьте следующий вариант.

Порядок:

1. **DiagD_CloneOnly.dll** — только клонированные типы мода, ни одного хука
   (публицизация членов при клонировании остаётся).
   - Если висит даже D — дальше можно не тестировать, сообщите об этом.
2. **DiagA_FullMinusGuiHooks.dll** — всё, кроме трёх GUI-хуков
   (`AcademyModalWindow.OnBeginShow/Hide`, `GuiHero.Title`,
   `HeroRecruitmentNotificationWindow.Refresh`).
3. **DiagB_FullMinusHeroHooks.dll** — всё, кроме хуков переделки героев.
4. **DiagC_HeroHooksOnly.dll** — только хуки героев, без Совета.

Сообщите результат по каждому варианту, который запускали
(«D — висит» / «D — меню, A — меню» и т.д.).

## Что будет означать результат

- D висит → дело в метаданных клонированных типов или публицизации.
- D ок, A ок → виновник один из трёх GUI-хуков.
- D ок, A висит, B ок → виновник в не-GUI хуках героев.
- A и B висят, C ок → виновник в хуках Совета.

## Заодно

Пришлите, пожалуйста, `EndlessSpace2_Data/output_log.txt` от запуска с
полной (обычной) DLL — Unity там часто пишет полный стек исключения с
именами типов, что сразу назовёт упавшую корутину загрузки окна.

После тестов верните на место обычный `Managed/Assembly-CSharp.dll`.
