# ES2 Hacking Modes — другая механика взлома для Endless Space 2

Мод меняет взлом: как только операция проложена, вы выбираете, **чем именно** она будет заниматься.
Вместо «довести взлом до конца и получить один разовый исход» можно оставить взлом висеть
подключённым к системе и доить её каждый ход.

## Что в репозитории

| Папка | Что это |
|---|---|
| `Managed/` | DLL самой игры (Assembly-CSharp.dll и прочее). Исходников игры нет — это скомпилированный код, он используется как справочник и как reference для компиляции мода. |
| `mod/src/` | Исходники мода (C#, плагин для BepInEx). |
| `dist/ES2.HackingModes.dll` | **Готовый собранный плагин** — его и надо положить в игру. |
| `.github/workflows/build-mod.yml` | Сборка мода прямо в GitHub Actions (компилирует `mod/src` против DLL из `Managed/`). |
| `docs/` | Разбор того, как устроен взлом в коде игры, и почему мод сделан именно так. |
| `build/build.log` | Лог последней сборки. |

## Режимы операции

Когда взлом нацелен на **систему большой империи**, в окне мода доступны три кнопки:

| Режим | Что делает | Скорость взлома |
|---|---|---|
| **Подглядывание за идеями** | Каждый ход вы получаете **20 % науки целевой системы**. Это копия: система продолжает получать свою науку полностью. | 0 |
| **Внедрение шпионов** | Пока операция подключена, в систему внедряется спящий: первый — сразу при подключении, дальше **раз в 5 ходов** (тот же приказ, что у ванильного исхода «внедрить агентов»). | 0 |
| **Пустить операцию** | Ваниль: взлом идёт дальше и завершается обычным исходом (кража технологий, саботаж, восстание и т. п.). | обычная |

Когда цель — **система малой фракции**, вариантов два:

| Режим | Что делает | Скорость взлома |
|---|---|---|
| **Воровство ресурсов** | Каждый ход вы забираете **20 % производства системы** (пыль / наука / влияние). Это именно воровство: малая фракция теряет столько же. | 0 |
| **Улучшение отношений** | **+10 к отношениям** с этой малой фракцией каждый ход. | 0 |

Третья кнопка «Пустить операцию» для малых фракций по умолчанию скрыта
(включается в конфиге: `AllowNormalOperation = true`).

### Как это работает по ходам

1. Вы прокладываете взлом до системы и запускаете операцию — **сразу открывается окно выбора режима**
   (его можно открыть в любой момент клавишей **F9** или кнопкой в левом верхнем углу).
2. Операция едет по маршруту как обычно.
3. Как только линия дотянулась до целевой системы, операция **замирает: скорость взлома 0**.
   Она больше не «вскрывает» систему и не исчезает с применением ванильного исхода —
   она просто висит подключённой и каждый ход приносит эффект выбранного режима.
4. Режим можно переключать в любой момент. Переключили на «Пустить операцию» — взлом поехал дальше
   и завершится нормально.

Если хотите, чтобы скорость обнулялась сразу при запуске (операция вообще никуда не едет,
а эффект капает с первого же хода) — в конфиге: `FreezeImmediately = true`,
`EffectsOnlyWhenConnected = false`.

## Установка

1. Скачайте **BepInEx 5.4.x (x64, Unity Mono)**: <https://github.com/BepInEx/BepInEx/releases>
   (файл вида `BepInEx_win_x64_5.4.23.2.zip`).
2. Распакуйте содержимое архива в папку игры — туда, где лежит `ES2.exe`
   (обычно `...\steamapps\common\Endless Space 2\`). Рядом с `ES2.exe` должны появиться
   `winhttp.dll`, папка `BepInEx` и `doorstop_config.ini`.
3. Запустите игру один раз и закройте — BepInEx создаст `BepInEx/plugins` и `BepInEx/config`.
4. Скопируйте `dist/ES2.HackingModes.dll` в `BepInEx/plugins/`.
5. Запустите игру. В логе `BepInEx/LogOutput.log` должна появиться строка
   `ES2 Hacking Modes 1.0.0 загружен`.

Удаление: просто удалите `BepInEx/plugins/ES2.HackingModes.dll` — игра вернётся к ванили,
файлы игры мод не трогает вообще.

## Настройки

После первого запуска появится файл `BepInEx/config/arena.es2.hackingmodes.cfg`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `Enabled` | `true` | Выключатель всего мода. |
| `SciencePercent` | `20` | Процент науки системы, который копируется вам. |
| `SleeperPeriod` | `5` | Раз во сколько ходов внедряется спящий. |
| `StealPercent` | `20` | Процент производства малой фракции, который воруется. |
| `StealHurtsVictim` | `true` | Вычитать ли украденное у малой фракции. |
| `RelationPerTurn` | `10` | Прибавка к отношениям с малой фракцией за ход. |
| `RelationCap` | `100` | Потолок отношений. |
| `AllowNormalOperation` | `false` | Показывать ли «Пустить операцию» для малых фракций. |
| `StealPercent` / `SleeperPeriod` | — | меняются на лету, перезапуск игры не нужен. |
| `EffectsOnlyWhenConnected` | `true` | Эффект только когда взлом дотянулся до системы. |
| `FreezeImmediately` | `false` | Обнулять скорость сразу при выборе режима. |
| `ToggleKey` | `F9` | Клавиша окна выбора режимов. |
| `AutoOpenOnNewOperation` | `true` | Открывать окно автоматически при запуске новой операции. |
| `ShowCornerButton` | `true` | Кнопка в углу экрана, когда окно закрыто. |
| `EnglishLabels` | `false` | Подписи на английском (если шрифт не тянет кириллицу). |

Выбранные режимы хранятся в `BepInEx/config/ES2HackingModes.state.txt` (по GUID операции),
поэтому переживают перезапуск игры и загрузку сейва.

## Что мод делает с игрой (технически)

Мод ничего не переписывает на диске — он патчит методы в памяти через Harmony:

| Метод игры | Патч | Зачем |
|---|---|---|
| `NodeHackingOperationStep.GetSpeedMultiplier` | postfix | вернуть 0 для пассивных режимов |
| `MoveHackingOperationStep.GetSpeedMultiplier` | postfix | то же для шагов движения |
| `HackingManager.ClientBeginTurn` / `ClientEndTurn` | postfix | раз в ход применить эффекты |
| `HackingManager.StartHackingOperation` | postfix | предложить выбор сразу после запуска операции |
| `HackingOperation.ClientBeginTurn` | prefix | не дать применить ванильный исход к «припаркованной» операции |

Эффекты используют штатные механизмы игры:

* наука/пыль/влияние — `DepartmentOfTheTreasury.TryTransferResources`;
* спящие — приказ `OrderSpawnTraitorPopulation` (тот же, что у ванильного исхода взлома);
* отношения — приказ `OrderSetMinorRelationPoints`.

Подробный разбор внутренностей взлома — в [`docs/как-устроен-взлом-в-ES2.md`](docs/как-устроен-взлом-в-ES2.md).

## Ограничения, о которых честно стоит знать

* Мод **не тестировался в живой игре** — он собран и проверен компилятором против ваших же DLL,
  но запустить ES2 в среде сборки невозможно. Первый запуск — за вами; если что-то пойдёт не так,
  в `BepInEx/LogOutput.log` будут подробные сообщения (мод всё оборачивает в try/catch и не роняет игру).
* Окно выбора режимов нарисовано средствами Unity IMGUI поверх игры, а не встроено в родной интерфейс
  взлома: GUI игры описан в XML-файлах `Public/`, и из плагина его расширить нельзя.
* Рассчитано на одиночную игру. В мультиплеере эффекты применяются на стороне клиента и могут
  разъехаться с сервером.
* Спящие внедряются ровно тем же приказом, что и ванильный исход, поэтому действуют те же
  ограничения игры (цель — колония большой империи, в системе есть место под предателей и т. д.).
  Если игра откажет, причина будет видна в логе.

## Сборка из исходников

Собирать не обязательно (готовый DLL лежит в `dist/`), но если нужно:

```bash
# На машине с .NET SDK или mono, BepInEx распакован куда-нибудь рядом:
BEPINEX_DIR=/путь/к/BepInEx/core ./mod/build.sh
```

Либо просто запушьте изменения — GitHub Actions соберёт `dist/ES2.HackingModes.dll` и
положит его обратно в ветку (лог сборки — в `build/build.log`).
